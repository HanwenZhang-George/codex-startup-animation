Repair scope since the preceding public R13 package
- R14 accepts supported local directory aliases for an officially registered
  installation root. It continues to reject remote, looping, unknown or
  escaping paths and retains signature, package and process identity checks.
  This does not authorize arbitrary links in the portable package directory.
- R14 also adds the official icon to Launch.exe; the original eight icon sizes
  are retained.
- R15 distinguishes a background official process from a verified main window
  and checks for the matching managed wallpaper session before replay. A
  background process without a window receives at most one official activation
  in an eight-second automatic budget. An unmanaged ordinary client prompts
  for a normal complete exit and retry; it is not killed or silently replaced.
- R16 fixes movie/transition close buttons and ordinary animation window-close
  paths that previously sent wallpaper disable during cleanup. These now use
  the skip path, retaining the current reveal intent and pending preparation.
  Preview, prior terminal disable, internal failure and system shutdown remain
  separate. A reveal request is not evidence that a frame has been displayed.
- R16 diagnostics record bounded, fixed-enum skip source and intent evidence.
  Provisional layout-not-ready samples are distinguished from terminal layout
  failures; old success cannot establish success for the latest attempt.
- Automatic registered-version discovery, bounded recovery, original media,
  memory protection and earlier warm-start/minimize safeguards are retained.

Limits and support
- R16 addresses an independently reproduced early-close defect. A separate
  historical terminal layout timeout (HOST166) was not proven to have the same
  cause; R16 does not claim to fix every layout mismatch or no-wallpaper case.
  Diagnostics preserve that failure separately from provisional readiness.
- Windows 10/11 x64, .NET Framework 4.8+, Windows PowerShell 5.1, a writable
  local NTFS directory and working Windows media components are required.
- Wallpaper transport supports the verified official Microsoft Store Codex
  Electron private CDP pipe. Tauri/Wry/WebView2 transport is not implemented.
- Ordinary registered version/path changes can be rediscovered. Identity,
  signer, framework, protocol or page-structure changes can need maintenance.
- Optional shortcut binding is per-user and reversible. Ordinary launch does
  not require recurring administrator authorization or a public debug port.
- Only Codex startup animation and wallpaper are included, not CC Switch,
  accounts or conversation records. Upstream attribution and font licenses
  remain; no new third-party media/code license is asserted.

How to report
- From the actual running copy, run Diagnostics/One-Click-Diagnostics.cmd.
  Send Diagnostics/Reports/latest-report.zip; latest-analysis.txt is readable
  locally. Collect before retrying and copy the ZIP aside to retain a failure.
- Detailed mode verifies every formal file hash, then collects bounded allowed
  records and numerical environment evidence. It attempts a report even if
  file verification finds damage. Full hashing reads media files, so duration
  depends on disk and security software. Report mode skips a new full hash pass.
- Diagnostics do not start, stop or wait for apps, use the network, install
  dependencies, decode videos or run CPU/GPU stress tests. No raw logs, chat,
  account files, command lines or API keys are intended export fields.
- Do not attach entire directories or raw logs. Review screenshots and text
  before posting a public GitHub Issue. Instructions and authorized feedback
  email addresses are in TROUBLESHOOTING.md.
