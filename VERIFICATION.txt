R10 repair scope
- Official client identity is resolved from the current user's registered
  package, its manifest application entry and a valid official signature.
  Generated policy no longer pins a fixed official version or EXE hash.
- Cold launch selects the target in the host and verifies the created process
  and its creation time against that selection. Later handoff stays bound to
  that actual process instead of independently choosing a newer version.
- Startup handoff now admits the observed late normal-to-hidden-maximized
  transition when exact owned placement and recovery checks still hold.
  Foreign placement, stale identity and initially minimized cases are not
  admitted by this correction. Existing bounded waits and rollback remain.
- Diagnostics distinguish configured automatic identity policy, successful
  identity verification, transport connection and actual media playback.
- R9 commit-headroom recovery remains: below 512 MiB pauses decoding; at least
  1 GiB continuously for 30 seconds permits a recovery request. A low physical
  memory notification alone does not permanently disable the wallpaper.
- Existing integrity, signature, process/session, private pipe, generation,
  startup resource and reversible-pause protections remain.

Support and privacy
- Run Diagnostics/One-Click-Diagnostics.cmd in the actual running copy.
  Fixed outputs: Diagnostics/Reports/latest-analysis.txt and latest-report.zip.
- Check-All-Files.cmd optionally verifies all formal file hashes; collect
  diagnostics again afterward to include its bounded verification summary.
- Support tools neither launch/close/wait for apps nor run CPU/GPU stress
  tests, download dependencies or upload anything automatically.
- Only allowlisted bounded diagnostic fields are exported. Do not submit raw
  logs, credentials, private keys, browser profiles or conversation data.
- Detailed instructions and explicitly authorized contact addresses are in
  TROUBLESHOOTING.md. Public commits use a GitHub noreply author address.

Supported boundary
- Windows 10/11 x64, .NET Framework 4.8+, Windows PowerShell 5.1, local writable
  NTFS directory and working Windows media components are required.
- Wallpaper transport supports the verified official Microsoft Store Codex
  Electron private CDP pipe. Tauri/Wry/WebView2 transport is not implemented.
  WebView2 marker files alone do not establish a client's runtime identity.
- Ordinary official version and manifest-entry path updates can be resolved
  automatically. Package identity, signer, framework, protocol or DOM changes
  can still require maintenance; universal future compatibility is not claimed.
- Existing ordinary Codex sessions without the managed wallpaper host cannot
  safely be retrofitted. Save work, exit normally, then use this Launch.exe.
- No public debug port is enabled. Unsupported identities/runtimes do not
  receive an unchecked wallpaper attachment.
- File integrity does not prove decoding or UI performance on every device.
- Launch.exe runs as a normal user. Optional Install-and-Bind.cmd is separate;
  it attempts a reversible binding to one trusted existing desktop shortcut.
- The author's stable local installations were not changed for publication.
  Public distribution includes no CC Switch, account settings or chat data.
- Upstream attribution and existing font license are retained; this project
  does not grant new rights to third-party code or media.
