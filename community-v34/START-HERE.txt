Codex 启动器＋动态壁纸 — V34-r9 内存策略修复候选完整包

这是完整包：启动动画、流泪转场、常态壁纸、粒子壁纸、全部源码和素材都在内。
这是供另一台电脑本地测试的候选包；尚未替换 GitHub 的 r5。
不包含 CC Switch。不覆盖已有安装，不迁移账号、对话或 API Key。

一、直接运行
1. 完整解压到一个新目录，例如 D:\Codex-Test-r9。不要覆盖旧包，也不要在 ZIP 内运行。
2. 保存工作，在测试电脑上正常完整退出 Codex。
3. 双击新目录最外层的 Launch.exe。无需运行 Install.ps1，也不需要管理员权限。
   没有弹出管理员授权是预期行为；不要通过管理员启动来绕过错误。
   官方桌面图标不会经过此便携包；从官方图标启动不能用来检验本包壁纸。
   如果已经从官方图标打开 Codex，请先正常完整退出，再用本包 Launch.exe。
4. 检查启动画面、流泪和波纹交接、进入 Codex 后的壁纸及输入框透明度。
5. 第一次固定常态视频；之后每次按 75% 常态、25% 粒子选择。
   两次出现之间保持原有 10–15 秒随机间隔。人物暂时离开不代表壁纸坏了。
6. 保持 Codex 打开，再双击同一个 Launch.exe，检查是否再次播放启动动画并回到
   原窗口，且原壁纸继续运行。再测试最小化后点击。不要同时连点启动多个副本。
7. 切换对话、改变窗口大小，确认输入、点击、壁纸正常。
   若启动等待过久，可以按 ESC 跳过并马上收集报告，不必等几分钟。

可选：绑定测试电脑原来的 Codex 桌面图标
便携测试正常后，正常退出 Codex，双击 Install-and-Bind.cmd。
它安装独立副本到当前用户目录，并尝试绑定当前用户桌面唯一的官方 Codex 快捷方式。
不需要每次管理员授权，不修改官方 Codex 程序；原快捷方式会单独备份后再替换。
如果目标安装目录已有文件、找不到唯一可信快捷方式或快捷方式类型不支持，会保守
停止或保留原入口并提示；不要删除其它安装来强行继续。公共桌面不自动处理。
安装后从原 Codex 图标启动，再验证一次重复启动。诊断请使用安装目录里的 Diagnostics，
不要收集旧解压目录的日志。需要还原时使用安装目录 Uninstall.ps1；不要直接删安装目录。

二、独立轻量诊断工具（正式版也保留）
进入 Diagnostics 文件夹，双击 One-Click-Diagnostics.cmd。
固定生成 Reports\latest-report.zip 和 Reports\latest-analysis.txt（中文分析）。
默认只读取已有日志、六段视频的存在性/大小、客户端兼容证据。
怀疑缺文件时，额外双击 Check-All-Files.cmd，核对全部正式文件 SHA-256 和程序框架。
完成后再次点击 One-Click-Diagnostics.cmd，可把完整文件核验摘要加入报告。
工具不启动、不关闭、不等待任何应用；不安装东西、不联网、不做整机压力测试。
完整测试顺序见该文件夹 README.txt。结果只放在 Diagnostics\Reports 内。
只保留最新一份，不堆积历史报告。发送 latest-report.zip，并补充哪些现象正常、哪里卡顿。
Ctrl+C 或关闭测试窗口可结束工具。无需在测试机运行 source/tests 开发测试。

三、正常诊断（正式程序保留）
也可以在解压目录打开 PowerShell，运行：
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Collect-DiagnosticReport.ps1"
它将 ZIP 写入 CodexDiagnosticReports。无需再次启动、等待播放或结束应用。
只输出数值、固定枚举、相对日志类别和允许的兼容标记，不导出原始日志、路径、
账号、聊天、API Key、窗口标题或进程命令行。不要上传运行后的整个目录。
快速报告里的媒体大小检查不等于重新做了哈希校验，更不等于解码成功。
兼容标记只是证据，不等于已证明运行时类型或壁纸传输支持。

四、本次修复和验证范围
- 修复 r8 壁纸后台准备阶段的第二道内存保护：它此前会在一次低内存预警后永久禁用
  本次壁纸，启动器保留播放请求也无法恢复。现在物理 RAM 偏低或 Windows 低物理内存
  通知不再单独作为停用依据；统一检查当前进程还能使用的提交内存余量。
- 只有可用提交内存低于 512 MiB 时暂停解码；恢复到至少 1 GiB 并连续稳定 30 秒后，
  从同一文件和页面会话恢复。不会重新安装或反复注入，也不会让启动界面等待这 30 秒。
  若内存持续接近耗尽，保持暂停；明确暂停、关闭或禁用仍优先。真实解码/传输错误
  仍可能失败，不能把“请求恢复”当成“已经播放”。报告明确区分这些状态。
- 首次准备遇到真正的内存压力时只保留文件引用，不先创建视频解码器再立刻释放。
  启动器自身内存超限、持续 CPU 超限、身份和完整性校验等保护继续保留。
- 修复只有壁纸后台察觉短暂内存压力、启动器却还在 59% 等待的分支：启动器核验
  同一宿主的新鲜暂停状态后释放启动画面，保留后续播放请求，不伪造准备完成。
以下 r8 修复继续保留：
- 资源保护释放启动动画，同时保留壁纸请求；不会用成功转场掩盖保护退出。
- 报告保留此前资源保护和随后重复启动失败的时间链，增加允许的具体保护原因。
  旧日志没有保存原因时仍显示未知，不把所有资源保护都解释为内存不足。
- 修复后台准备尚在进行时，后续显示请求过早耗尽等待预算并被丢弃的竞争；
  总退出清理仍最多 3 秒，不重试已提交的命令，也不把明确禁用改回开启。
- 失败回滚时，为可能迟到的隐藏请求安排一次不抢焦点的显示补偿，保留用户最小化
  和移动状态。没有目标窗口的完成确认时，800 毫秒保护预算后仍标为“未确认”，
  并保留小型恢复记录；未确认不等于窗口一定恢复失败。正常交接不走此保守分支。
以下 r7 修复继续保留：
- 重复启动读取已有进程时改用所需的最小查询权限；保留进程创建时间、路径、注册包、
  哈希及本地会话验证。增加固定阶段/错误码记录，不导出路径、进程号或异常正文。
- 报告分别显示最近完整启动耗时和后续重复点击失败，避免旧的播放成功记录掩盖新问题。
- 可选安装绑定当前用户原官方桌面快捷方式；日常普通权限启动，卸载可核验后还原。
- 上次报告的完整启动约 30.7 秒，约 18 秒在等待客户端页面和布局就绪。此包不通过
  删除动画、降低画质或缩短必要校验等待来掩盖慢启动，也不保证每台电脑启动更快。
以下 r6 修复继续保留：
- 修复输入框延迟挂载或更新类名后，透明样式缓存没有重新绑定的问题。
- 样式使用本项目标记和严格页面结构，不再单凭 electron 文字标签判断布局。
- 修复高对比度/强制颜色模式的外框回退优先级，保障可读性。
- 启动宿主只检查本 Windows 会话内的既有客户端，避免其他会话误阻止启动。
- 报告增加布局拒绝细项、六个视频文件状态、注册客户端版本及运行时标记。

全部 46 项媒体/字体/素材、其中 6 个 MP4 保持原始 SHA-256。
没有重编码、降分辨率、码率、视频帧率、绘制帧率，也没有改动常态透明度参数。
隔离回归测试不能代替另一台电脑实际播放与操作，也不是长时间稳定性承诺。
本包没有实现或声称适配未验证的 Tauri/Wry 客户端。实际宿主仍是经过校验的
官方 Store Electron 客户端及私有本地调试管道；不开放网络调试端口。
如果另一台电脑使用其他运行时，报告会提供证据供继续适配，不会虚报成功。
