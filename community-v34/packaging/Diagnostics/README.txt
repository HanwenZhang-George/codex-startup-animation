完整问题反馈工具（正式版也保留，所有输出与程序文件隔离）

请先正常运行并复现问题，再双击实际运行目录中的 One-Click-Diagnostics.cmd。
不需要先关闭 Codex，也不需要管理员权限。不要为了诊断反复启动或长时间等待。
一键流程会先核对包内程序和全部素材的 SHA-256，再收集有限日志和系统环境。
文件校验失败、媒体缺失或清单损坏时，仍会尽量生成同一份反馈报告；
若诊断辅助脚本本身缺失/损坏、输出目录不能写入，则会明确提示，旧报告不会冒充新结果。
固定输出：
  Diagnostics\Reports\latest-report.zip    发回给维护者的报告
  Diagnostics\Reports\latest-analysis.txt  自己查看的中文分析
每次更新最新一份，不堆积历史 ZIP。要保留历史，请自行另存上一份。

默认做完整文件哈希；这只顺序读取本包文件，不解码视频，不运行显卡/CPU压力测试，
不启动或关闭任何应用。校验完成后读取有限日志、已注册官方客户端的固定兼容标记、
六段视频的存在性/大小，以及系统版本、CPU逻辑数、内存数值、屏幕尺寸/缩放、
显卡厂商枚举和纯数字驱动版本/日期、诊断进程权限。
不下载东西、不联网、不安装依赖、不扫描全盘、不读取账号配置/聊天/进程命令行。
报告只输出允许的数值、枚举和标记，不导出原始日志、真实路径或 API Key。
页面结构证据同时覆盖启动准备和进入 Codex 后的变化，仍使用原有记录频率。
最近的公开入口固定错误码会单独分析，避免上一次的播放成功掩盖这次入口失败。
旧日志没有启动/预览/校验模式标记时会注明无法确认，不推断客户端已经关闭。
中文分析是基于现有日志的判断，不会把旧记录冒充当前状态或承诺不存在其他问题。
系统环境采集单独采用最多2秒的协作式预算（不等于所有系统调用都能强制超时），每类日志最多读取256KiB、保留512条允许的事件。
报告会标记被截断/丢弃的记录数量，JSON单项上限8MiB；不会无限收集或堆积历史。
显卡登记信息不代表实际渲染使用的显卡，也不是性能测试。
完整哈希需读取包内视频，通常数秒，慢磁盘或杀毒软件检查可能延长；Ctrl+C可结束工具。

如果只想检查文件，双击 Check-All-Files.cmd 做完整 SHA-256 校验。
它顺序读取包内文件，不解码视频、不跑显卡，校验结果保存在 Reports\file-check.json。
反馈问题时直接双击 One-Click-Diagnostics.cmd 即可，不用先分别运行两个工具。
报告将记录失败的清单序号（从0开始）、文件用途枚举及缺失/大小/哈希等原因，
不会输出实际文件路径。完整哈希通过不等于画面播放、解码、焦点或适配一定正常。
仅收集现有日志的快速模式仍可使用：在本目录打开Windows PowerShell，运行
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Run-Diagnostics.ps1 -Mode Report
快速模式不重新做完整哈希，只会采用与当前清单匹配的既有文件校验结果。
工具脚本本身很小，图像视频素材才是这个包的主要体积；不会额外生成视频或截图。

首次测试建议：
1. 完整解压到新文件夹，运行完整文件校验。
2. 保存工作并正常完整退出 Codex，再双击上一级的 Launch.exe。
   未绑定的官方图标会绕过本便携包。可选安装绑定成功后，应在安装目录收集报告。
3. 观察启动、眨眼、流泪、波纹、常态壁纸。卡住时可按 ESC，立即生成报告。
4. 切换/新建对话、展开侧栏、调整大小、最大化/最小化恢复，检查输入框与按钮。
5. 打开 WallpaperControls.exe，暂停再恢复。
6. 由本包启动 Codex 后，再点击一次 Launch.exe，检查重复启动处理。
   然后把原窗口最小化，再点击 Launch.exe；检查是否回到同一窗口。
   原窗口应继续使用，壁纸保留；识别失败会提示收集报告，不会强制重启 Codex。
7. 完整退出后再启动一次，按 ESC，检查进入 Codex 后的壁纸。
8. 有余力再测试系统重启后第一次启动，不需要跑长时间压力实验。
9. 最后双击 One-Click-Diagnostics.cmd，将 Reports\latest-report.zip 发回；
   补充在哪一步出问题、是否卡顿、是否出现黑框。可附最新截图，不必发原始日志、
   整个程序目录、账号配置或聊天记录。分析文字保存在同目录latest-analysis.txt。

正常轮播：第一次常态；以后每次 75% 常态、25% 粒子。
角色两次出现之间有原有 10–15 秒间隔；不是每四次必定出现一次粒子。
普通方式已运行的 Codex 无法补接私有管道：请完整退出，再从本包 Launch.exe 启动。
未知运行时标记不等于已确认 Tauri，也不等于本包已实现对应通信适配。
不用在用户电脑运行 source/tests 开发回归；这些是给开发者的测试源码。

官方更新后的适配检查：
1. 从新解压目录的 Launch.exe 启动。普通版本号或安装路径变化会重新读取
   Windows 当前用户注册信息，并核对官方签名；不需要手改官方 EXE 哈希。
2. 如仍没有壁纸，直接生成报告；工具只摘录识别策略的版本/模式/旧固定字段
   是否存在及固定身份验证结果，不导出原始配置、进程身份或安装路径。
3. 配置存在、签名验证通过、客户端已经启动，都不单独代表壁纸播放成功。
   若官方更换包标识、签名身份、界面结构或底层框架，仍可能需要新的适配。

R14 补充：官方身份拒绝时记录固定原因和启动/校验/配置模式；安装根目录检查
区分路径缺失、权限、联接与元数据不可读。受支持的官方本地目录联接可解析后
检查真实目录。目录可读不等于签名有效，更不等于壁纸已经播放。
首次失败后立即收集报告，并在再次尝试前另存 ZIP；不要修改系统目录权限。

R15 补充：报告保留本次入口的冷启动、重播、一次激活、等待用户退出及取消等
固定路由原因，并区分同目录宿主会话、暂停/禁用/故障状态和仅动画重播。
仅动画及窗口交接成功不证明壁纸已经准备或正在播放；较早宿主的持续播放
不能替代这次点击的结果。路由耗时可能包含用户选择等待，不能当成自动探测耗时。
没有可接入的同目录宿主时，先保存工作并正常完整退出 Codex，再从本包启动。
诊断本身仍只收集既有记录，不执行激活、退出、恢复壁纸或显卡测试。
